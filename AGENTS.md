# AGENTS.md

Public documentation for RevenueDot. Follow `prd/ecosystem/PRD.md` in revenuedot/revenuedot.

- **API reference pages are generated, never hand-edited.** Edit `scripts/openapi/*.mjs` (the OpenAPI source), then `npm run build`. `npm run check:drift` compares the document with the server's route files in `../revenuedot`; fix the spec whenever the server changes.
- **Every page has frontmatter** (`title`, `description`) and one H1 equal to the title. `npm run check:pages` enforces it.
- **Reference pages are generated from data, never hand-edited.** `data/errors/*.json` becomes `docs/errors/` (Apple StoreKit 2 errors, Google Play Billing response codes, purchases SDK error codes), `data/notifications/*.json` becomes `docs/notifications/` (App Store Server Notifications v2 types and subtypes, Google Play real-time developer notification types) and `data/webhooks/*.json` becomes `docs/webhooks/` (the RevenueDot webhook event types). Edit the data file, run `npm run build`; `npm run check:errors` is the quality gate for all three (a vendor source link, a link to the RevenueDot source file for any behavior it states, a code block, cause and fix sections, a unique one-sentence answer, a unique description and example, 170 words minimum, webhook events present in `api/webhook-events.md`, and no drift from the data file). A thin entry is not generated. Take causes only from the vendor's page or the SDK and server source and link it; never invent one. `npm run check:snippets` type-checks Swift snippets on a Mac and runs Node snippets anywhere (they must print the entry's `expect` text); Kotlin snippets are marked "Not compiled". A new family of pages also needs a section in `scripts/gen-llms.mjs` and in the site's `SECTIONS` (`apps/site/src/lib/docs.ts` in revenuedot/revenuedot).
- **Keep `llms.txt`, `llms/` and `llms-full.txt` in sync**: run `npm run build:llms` after any page change. A new folder of pages needs a section in `scripts/gen-llms.mjs`.
- **Pull requests run the deploy's checks** (`.github/workflows/ci.yml`: `npm run all`, generated pages committed, then the site's build and check against revenuedot/revenuedot). If your change goes with a server change, open this pull request from a branch with the same name as the server one and the CI pairs them; merge the server pull request first.
- **Before committing:** `npm run build && npm run check` must pass. A push to `main` deploys revenuedot.app (`.github/workflows/deploy-site.yml`), so check that the site renders the pages too: `pnpm --filter site build && pnpm --filter site check` in `../revenuedot`.
- Every claim about RevenueCat or another vendor needs a source link. Never copy RevenueCat's docs text or anything from revenuedot/company.
- Record progress in `docs/STATUS.md` in revenuedot/revenuedot. Private material goes to revenuedot/company.
